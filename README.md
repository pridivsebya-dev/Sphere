# ElytrixAddonSphere

Аддон для плагина **BCases** (by1337), добавляющий анимацию открытия кейса **`elytrix:sphere`** — «Орбита».

Призы каскадом взлетают на наклонную орбиту и кружат вокруг кейса со шлейфами
из частиц; орбита ускоряется, сжимается в вихрь, проигравшие предметы исчезают
каскадом вспышек, а победитель взмывает над кейсом, парит в покачивании
в спирали частиц под звук победы.

## Сборка

```bash
cd ElytrixAddonSphere
mvn package
```

Готовый jar: `target/ElytrixAnimAddon-1.5.jar` (требуется JDK 17 и доступ к
`repo.by1337.space` — там лежат BCases-common и VirtualEntityApi).

## Установка

1. Положите `ElytrixAnimAddon-1.5.jar` в папку аддонов BCases (обычно `plugins/BCases/addons/`).
2. Перезапустите сервер — при первом запуске создастся
   `plugins/BCases/animations/sphere/sphereAnimation.yml`.
3. Укажите анимацию `elytrix:sphere` в настройках кейса.

## Конфигурация (`sphereAnimation.yml`)

| Ключ | По умолчанию | Описание |
|---|---|---|
| `radius` | `2.5` | Радиус орбиты в блоках (0.8–6.0) |
| `itemCount` | `10` | Предметов на орбите (4–24) |
| `rotationSpeed` | `7.0` | Базовая скорость орбиты, °/тик (1.0–20.0) |
| `precession` | `30` | Максимальный наклон орбиты, ° (0–70) — орбита непрерывно наклоняется до него и обратно |
| `height` | `1.2` | Высота орбиты над кейсом (0.0–4.0) |
| `particleVector` | `REDSTONE` | Частицы-шлейф за предметами |
| `particleItems` | `REDSTONE` | Частицы вокруг победителя |
| `red` / `green` / `blue` | `255/105/180` | Цвет частиц `REDSTONE` |
| `showItemNames` | `1` | Имена предметов над ними (1/0); `0` — меньше нагрузки |
| `timings.ascentSteps` | `5` | Тиков разгона предмета при взлёте |
| `timings.ascentGap` | `2` | Тиков между запусками предметов (каскад) |
| `timings.orbitTicks` | `150` | Длительность основной фазы орбиты |
| `timings.tiltCycleTicks` | `80` | Период цикла наклона орбиты: непрерывно от 0° до `precession` и обратно |
| `timings.convergenceTicks` | `40` | Длительность сжатия в вихрь |
| `timings.winnerTicks` | `45` | Длительность показа победителя |
| `timings.trailPeriod` | `2` | Шлейф раз в N тиков; `0` — выкл. |
| `timings.spawnSound` | `BLOCK_NOTE_BLOCK_PLING` | Звук запуска предмета |
| `timings.winSound` | `ENTITY_PLAYER_LEVELUP` | Звук победы |

Любой ключ можно удалить — подставится значение по умолчанию. Полностью битый
файл конфигурации не ломает анимацию: она откатывается к встроенным дефолтам.

## Почему эта версия не должна лагать

Предыдущая версия («сфера» с каркасом) слала ~150–220 пакетов частиц каждый тик —
отсюда фризы при нестабильном пинге. Новая версия легче на порядок:

* шлейфы — по 1 частице на предмет раз в 2 тика (≈5 пакетов/тик вместо сотен);
* вспышки и салют — один пакет на много частиц сразу (`count > 0`);
* убран `lookAt()` каждый тик — предметы крутятся родной ванильной анимацией клиента;
* никакого «провода»-каркаса, который рисовался десятками пакетов каждый тик.

Если хочется ещё легче: `trailPeriod: 3` (или `0`), `showItemNames: 0`,
`itemCount: 8`.

Единственный оставшийся источник микровздрагиваний — сам VirtualEntityApi:
раз в 30 тиков он принудительно шлёт `TeleportEntityPacket` (условие
`tick % 30 == 0` в `updateLocation()`), который клиент применяет без
интерполяции. Из аддона это не обходится; лечится только пересборкой
VirtualEntityApi-core с правкой условия (например, `tick % 600 == 0`).
