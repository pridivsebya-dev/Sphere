# ElytrixAddonSphere

Аддон для плагина **BCases** (by1337), добавляющий анимацию открытия кейса **`elytrix:sphere`**.

Призы вылетают из центра кейса и выстраиваются в вращающуюся 3D-сферу, соединённую
каркасом из частиц. Сфера вращается, плавно сжимается и схлопывается в центр,
где остаётся единственный победивший предмет.

## Сборка

```bash
cd ElytrixAddonSphere
mvn package
```

Готовый jar: `target/ElytrixAnimAddon-1.1.jar` (требуется JDK 17 и доступ к
`repo.by1337.space` — там лежат BCases-common и VirtualEntityApi).

## Установка

1. Положите `ElytrixAnimAddon-1.2.jar` в папку аддонов BCases (обычно `plugins/BCases/addons/`).
2. Перезапустите сервер — при первом запуске создастся
   `plugins/BCases/animations/sphere/sphereAnimation.yml`.
3. Укажите анимацию `elytrix:sphere` в настройках кейса.

Требования к серверу: версия с поддержкой BCases + VirtualEntityApi 1.4.2+ и BLib.

## Конфигурация (`sphereAnimation.yml`)

| Ключ | По умолчанию | Описание |
|---|---|---|
| `radius` | `2.5` | Радиус сферы в блоках (0.5–8.0) |
| `itemCount` | `12` | Предметов на сфере (4–64). `12` — идеально ровный икосаэдр, иначе сетка Фибоначчи |
| `shrink` | `0.78` | Сжатие радиуса к концу вращения (0.3–0.95) |
| `rotationSpeed` | `3.0` | Максимум градусов/тик при вращении (0.5–8.0) |
| `particleVector` | `REDSTONE` | Частицы каркаса; `REDSTONE` красится цветом ниже |
| `particleItems` | `REDSTONE` | Частицы-аура предметов (вкл. через `itemAuraPeriod`) |
| `red` / `green` / `blue` | `255/105/180` | Цвет частиц `REDSTONE` |
| `showItemNames` | `true` | Имена предметов над ними; `false` — меньше нагрузки на клиент |
| `timings.rotationTicks` | `160` | Длительность вращения в тиках |
| `timings.spawnSteps` | `6` | Тиков полёта предмета из центра на место |
| `timings.finalCollapseTicks` | `20` | Тиков сжатия сферы в центр |
| `timings.finalHoldTicks` | `15` | Тиков удержания победителя в центре |
| `timings.wireframeDelayTicks` | `3` | Задержка каркаса — эффект «шлейфа» |
| `timings.wireframePeriod` | `1` | Рисовать каркас раз в N тиков; `2`+ — меньше пакетов при лагах |
| `timings.wireframeStep` | `0.5` | Шаг частиц вдоль ребра, блоки |
| `timings.wireframeIndent` | `0.35` | Отступ частиц от краёв ребра |
| `timings.itemAuraPeriod` | `0` | Раз в N тиков давать ауру предметам; `0` — выкл. |
| `timings.spawnSound` | `BLOCK_FIRE_EXTINGUISH` | Звук появления предмета |
| `timings.winSound` | `ENTITY_EXPERIENCE_ORB_PICKUP` | Звук победы |

Любой ключ можно удалить — подставится значение по умолчанию. Полностью битый
файл конфигурации не ломает анимацию: она откатывается к встроенным дефолтам.

## Технические заметки о плавности

* Позиции предметов обновляются каждый тик через VirtualEntityApi; обычные
  move-пакеты клиент сглаживает сам, поэтому основной такт анимации плавный.
* В VirtualEntityApi (включая 1.4.2) каждые **30 тиков** принудительно
  отправляется `TeleportEntityPacket` (код `updateLocation()`,
  условие `tick % 30 == 0`) — клиент применяет телепорт без интерполяции,
  из-за чего каждый предмет раз в ~1.5 с едва заметно «вздрагивает».
  Это ограничение библиотеки, из аддона оно не обходится. Если хотите
  идеально гладкое вращение — пересоберите VirtualEntityApi-core с правкой
  этого условия (например, `tick % 600 == 0`).
* Аддон сознательно не шлёт пакеты скорости каждый тик (`setNoMotion()`
  вызывается один раз при спавне) — так раньше появлялось ~16 лишних
  пакетов за тик на игрока.

### Если анимация лагает или фризит

Сначала определите, где лаг: введите на сервере `/tps` во время анимации.

* **TPS проседает ниже ~18–19** → не тянет сервер/хостинг. Снижайте нагрузку:
  * `timings.wireframePeriod: 2` (или 3) — каркас рисуется в 2–3 раза реже;
  * `showItemNames: false` — убирает таблички имён (дороги в рендере клиента);
  * `timings.wireframeStep: 0.7` — крупнее шаг частиц вдоль рёбер;
  * `itemCount: 12` (дефолт) — меньше предметов, меньше пакетов.
* **TPS ровно 20, но картинка дёргается** → это клиентская сторона: FPS-просадка
  у игрока (помогают пункты выше) либо микровздрагивание предметов раз в ~1.5 с —
  тот самый принудительный телепорт из VirtualEntityApi (см. выше).
